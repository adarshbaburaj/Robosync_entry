Cause and intended preprocessing
-------------------------------
The original encode_obs/_extract_image path yields contiguous CHW RGB uint8
pixels in [0,255], including when the simulator supplies batched RGBA cameras.
NPZ transport preserves dtype. torch.from_numpy also preserves uint8. All five
selected SmolVLA checkpoints specify VISUAL=IDENTITY, so their preprocessor
does not cast or divide image pixels. SmolVLA.prepare_images expects floats
in [0,1] before bilinear resizing and then maps them to [-1,1] for SigLIP.
The organizer's CUDA resize kernel rejected Byte input before any valid action.
A dependency downgrade does not supply the missing conversion.

prepare_observation() now converts observation.images.* tensors using
torch.from_numpy(value).to(torch.float32).div_(255.0) for uint8 input, BEFORE
the saved checkpoint processor or model resizing. Already-normalized floating
images are cast to float32 without a second division. Non-finite/out-of-range
floating images and other integer dtypes fail explicitly. State, velocity and
force values retain their original dtype and units; their saved checkpoint
normalization still applies. RGB order, camera mapping, gripper handling,
action chunk length, task selection and all checkpoint weights are unchanged.

Validation and limits
---------------------
python -m unittest submission.test_smolvla_images -v
python submission/probe_smolvla_worker.py all --device cpu \
  --output submission/smolvla_correction_validation.json

Regression assertions cover byte-to-float pixel correspondence, removal of
RGBA alpha via the existing encoder, no double scaling, unchanged state units,
invalid range rejection, and upstream prepare_images output in [-1,1].
The CPU resize kernel accepts Byte, unlike the reported CUDA kernel, but
the original Byte path still produces the wrong range after SigLIP scaling.
Thus the tests explicitly inspect pixel dtype/range instead of relying on
the presence or absence of a CPU runtime exception.

The real worker probe uses three synthetic 480x640 RGBA uint8 simulator-shaped
camera observations with nonconstant pixels covering 0 and 255, runs encode_obs,
NPZ transport, saved processors and real checkpoint inference. Two fresh calls
per checkpoint, with episode resets, each must return finite [10,14] actions.
Machine-readable evidence: submission/smolvla_correction_validation.json.
Original float-only probe results are retained in validation_results.json;
they missed this bug and do not establish byte-camera compatibility.

Validation is on an Apple Silicon CPU using the exact LeRobot revision and
PyTorch 2.7.1. No claim of local CUDA/simulator or held-out success is made.
The organizers must freeze this immutable correction and rerun the paused
SmolVLA tasks through their official workflow. Previous ACT/DP evidence remains
an organizer audit record; this patch does not imply any evaluation score.
